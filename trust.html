// HOW THE HEARTBEAT WORKS
Four steps, every six hours, no human in the loop.
01 · FETCH

Re-download the live bundle

A scheduled job pulls the actual hardseal_edge_trophy_case.zip from hardseal.ai — the same file a customer would — cache-busted, no shortcuts.

02 · VERIFY

Hash + per-packet check

It confirms the bundle's SHA-256 matches the published sidecar, then runs the standalone verifier on every packet inside. PASS only if all of it holds.

03 · CHAIN

Sign into the chain

The result is written as guardian_sha = sha256(previous_line || this_line), linking each receipt to the one before it. The history becomes tamper-evident.

04 · PUBLISH

Commit — PASS or FAIL

The line is committed to the public log and this page is regenerated. FAILs are committed too, then surfaced as alerts. Nothing is swept.

Every number here is reproducible from primary sources. Three ways in, from fastest to most paranoid:

1. Read the raw log. Open INTEGRITY_LOG.md and count the lines yourself. Each one is a receipt.

2. Re-run a packet. Download verify_standalone.py (Python standard library only, no phone-home) and run it against a sample packet in your own terminal.

3. Re-derive the entire chain with one command. Download verify_chain.py (Python standard library only — no network, no Hardseal service) and run it against the log:

curl -sO https://raw.githubusercontent.com/ricojallen37-sketch/hardseal-website/main/scripts/verify_chain.py
curl -sO https://raw.githubusercontent.com/ricojallen37-sketch/hardseal-website/main/docs/integrity/INTEGRITY_LOG.md
python3 verify_chain.py INTEGRITY_LOG.md
